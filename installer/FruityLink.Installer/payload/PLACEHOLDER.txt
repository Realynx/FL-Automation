FruityLink installer payload directory
======================================

The installer copies the files in THIS folder into the FL Studio program directory at install
time. The set of files is described by the manifest (Core/InstallManifest.cs, or an external
manifest.json placed next to the installer EXE). Run `FruityLink.Installer --print-manifest` to
see the effective manifest.

Expected contents for the default (RealLoader / version.dll proxy) layout:

  version.dll          - our proxy DLL (forwards the 15 Ver* exports to System32\version.dll and
                         bootstraps FruityLink). Backs up FL's existing version.dll (if any) to
                         version.dll.flbak before overwriting.
  FlBridge.dll         - the native C++ control SDK (built from tools/bridge).
  FlClrHost.dll        - the CLR host that boots .NET in-process (user-provided; name is a
                         placeholder until re/integration-pending-proxy.md lands).
  managed\             - the managed app assemblies + *.runtimeconfig.json / *.deps.json.

This file is only a placeholder so the folder exists in source control and in the build output.
The real binaries are dropped here by the release/packaging step. `--self-test` builds its own
throwaway payload in a temp directory, so it does NOT need these files.
